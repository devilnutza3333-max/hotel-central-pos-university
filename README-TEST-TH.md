# Hotel Central POS — ชุดตรวจสอบก่อน Deploy (12 พฤศจิกายน 2569)

## สถานะที่ตรวจได้ใน ChatGPT
- ยืนยันจากภาพ Dashboard ว่าข้อผิดพลาด 246 ครั้งเป็น `Exceeded CPU Time Limits` 246 ครั้ง ไม่ใช่ `Exceeded Memory`.
- ไฟล์ CPU Patch มีการแก้ไขการโหลด `order_items` ให้สอดคล้องกับช่วงออเดอร์ที่ส่งกลับ และลดการรีเฟรชหน้า POS จาก 6 เป็น 12 วินาที พร้อมหยุดเมื่อซ่อนแท็บและกันเรียกซ้อน.
- ตรวจสอบความครบของ ZIP, ไวยากรณ์ไฟล์ TypeScript/TSX, กฎ patch, และผล SQL เทียบกับข้อมูลจำลองได้
- ไม่ได้เชื่อม D1 จริง ไม่ได้ Deploy และไม่สามารถยืนยันว่า CPU ต่ำกว่า 10 ms ต่อคำขอบน Cloudflare จนกว่าจะได้ทดสอบออนไลน์

## ทดสอบ Build บน Windows แบบคลิกเดียว
1. แตกไฟล์ ZIP นี้ลงโฟลเดอร์ใหม่บนคอมพิวเตอร์ Windows
2. ต้องมี Node.js เวอร์ชัน 22 หรือใหม่กว่า และมีอินเทอร์เน็ตสำหรับดาวน์โหลด dependencies
3. ดับเบิลคลิก `TEST-WINDOWS.cmd`
4. โปรแกรมตรวจโครงสร้าง patch โดยใช้ `node --test`, ติดตั้ง dependencies ด้วย pnpm และสั่ง Build
5. ถ้าขึ้น `SUCCESS` หมายถึง **ทดสอบ Build ผ่านเท่านั้น** ไม่ได้แปลว่า Error 1102 หายแล้ว
6. หากขึ้น FAILED ให้ส่งภาพข้อความสีแดงหรือบรรทัดสุดท้ายมาเพื่อแก้ไขต่อ

## ไม่ควรทำระหว่างการทดสอบ
- อย่ากด Deploy ขึ้น Production หรือ Execute Migration บน D1 จริง
- อย่าส่ง API token, session cookie, `.env`, `.dev.vars` ที่มีความลับลงแชท
- อย่าสร้างฐานข้อมูลใหม่ทับของเดิม

## ขั้นตอนออนไลน์ในอนาคต (ต้องมี staging ก่อน)
1. สร้างฐานข้อมูล D1 ทดสอบต่างหากจาก `hotel-central-pos-db` หรือใช้ฐานข้อมูลจำลองในเครื่อง
2. ตรวจการ bind `DB` กับ D1 ทดสอบ และเตรียม migration สำหรับ DB ทดสอบเท่านั้น
3. Deploy staging Worker คนละชื่อกับ `hotel-central-pos-university` เพื่อป้องกันเขียนทับ
4. ทดสอบสั่งอาหาร คิดเงิน ชำระเงิน พิมพ์ใบเสร็จ ครัว บาร์ สต๊อก QR และสิทธิ์ผู้ใช้
5. ติดตาม `Metrics > Errors by invocation status` ดูว่า Exceeded CPU Time Limits เป็น 0 ในสถานการณ์ทดสอบ และตรวจ CPU distribution ต่อยอดโหลดจำลอง
6. สำรอง Production D1 และตรวจ migration ก่อนปล่อยเวอร์ชันจริง

> หมายเหตุ: หากต้องทดสอบสมรรถนะจริง ต้อง Build และรัน Worker พร้อมฐานข้อมูล D1 ทดสอบ ในสภาพแวดล้อม Cloudflare; การผ่าน Unit/Static checks ไม่เท่ากับผ่าน Cloudflare CPU.
